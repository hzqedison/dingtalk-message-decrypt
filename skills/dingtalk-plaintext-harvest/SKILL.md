# 钉钉群明文抓取（dingtalk-plaintext-harvest）

## 什么时候用

- 需要读取、汇总、分析某个钉钉群的聊天内容
- dws 等工具读到的是 `[加密消息，无法解码]`（企业启用了第三方加密）
- 需要导出群消息做整理、备份、统计

## 原理（理解它才能排查问题）

钉钉 PC 客户端能把加密消息**解密显示**给用户看，说明明文一定短暂存在于进程内存里。
本工具不碰密钥、不逆向算法、**不控制钉钉窗口**，而是：

1. 后台监听钉钉主进程的内存
2. 抓取**显示层字段 `content.text`**（用户实际看到的文字，不是 origin_text）
3. 只保留附近带目标群 cid 标记的（过滤掉其他群）
4. 持续累积去重，结束后按主题分类输出 markdown

**关键**：是被动监听，不是主动控制。用户正常浏览钉钉，脚本在后台静默抓取——
用户翻到哪段，那段消息就会被客户端解密进内存，脚本就抓下来。

## 前提条件（缺一不可）

- Windows 系统（依赖 Win32 API 读进程内存）
- **Python 3.9+**（纯标准库，无需 pip 安装任何依赖）
- 钉钉 **PC 客户端已登录**
- 目标群**已在客户端里打开过**（没打开过 = 从没解密过 = 内存里没有）

## 用法

```bash
cd <skill 目录>
python harvest.py                    # 后台监听 5 分钟
python harvest.py --seconds 600      # 自定义监听时长
python harvest.py --mark AbCdEf      # 只抓某个群：cid 特征片段（留空=抓所有群）
python harvest.py --name "群名"      # 报告标题
```

启动后**不用管它**，让 agent 或用户正常在钉钉里浏览群消息即可。想抓哪段历史，就在钉钉里滚到那段让它显示出来。

`--mark` 怎么拿：群的 `openConversationId`（形如 `cid/AbCdEf123456==`），取其中一段独特字符串即可，
例如 `cid/AbCdEf123456==` 就传 `--mark AbCdEf`。cid 可用 `dws chat +list` 或 dws 拉取的消息 JSON 里看到。
**不传 `--mark` 则不做群过滤**，会把客户端当前可见的所有明文都抓下来（输出可能混了多个群）。

## 输出

脚本目录生成 `群明文_<群名>_<时间戳>.md`，按主题分类，内容全部可读。

## 作为读取消息的前置步骤（推荐工作流）

当 agent 要读取/汇总一个加密钉钉群时：

1. **先在后台运行本脚本**（它会持续抓取明文）
2. 同时用 dws 拉取结构化消息（拿到时间、发送人、密文）
3. 两者结合：dws 提供时间轴和发送人，本脚本提供密文消息的内容

这样即使加密消息的密文读不出，也能拿到它们的**内容**。

## 局限（要如实告诉用户）

- 只能拿到"客户端曾显示过"的消息明文；从没加载过的抓不到
- 显示层不存时间戳，抓到的内容**大多没有精确时间**（要时间需结合 dws）
- 被动监听依赖用户/agent 浏览覆盖，覆盖多少取决于浏览了多少
- 钉钉大版本升级后内存结构可能变化，需重新验证

## 文件

- `harvest.py` —— 被动监听抓取主脚本（自包含，纯 ctypes，无第三方依赖，不依赖 powershell）
- `_memfinal2.py` —— 可选补抓：扫进程内存里的 `origin_text` 字段并导出 `mem_plain2.json`，
  `harvest.py` 会自动合并它的结果。**没有这个文件时脚本会跳过该步，只依赖显示层，功能不受影响。**
